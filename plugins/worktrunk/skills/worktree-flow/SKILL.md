# Worktrunk の手順

- 開始前に `git status --short`、`git worktree list`、ブランチと基点コミットを確認する。新規作成は `wt switch --create feature/<topic> --base <base> --no-hooks` を基本とし、既存ブランチの再利用時も `--no-hooks` を付ける。命名はリポジトリ指定を優先し、既存変更の無断移動・上書きをしない。
- Claude Code の sandbox の中では `wt switch --create` が `.git/worktrees` に書けずに失敗する。`~/mac_home/hooks/wt-create` で作った worktree も、Claude からは同じ理由で commit できない（settings.json の allowWrite でも開かない）。Claude が自分で直すときは、メインの作業ツリーに未コミットの変更がなく、ほかのセッションも使っていなければ、そこで `git branch --no-track feature/<topic> origin/<基点>` で作り、次の呼び出しで `git switch feature/<topic>` に切り替えて作業する（`--no-track` がないと upstream を `.git/config` に書けずに途中で止まる。`git switch -c` は auto mode の判定に止められる）
- worktree での作業は `cd` だけの1回の呼び出しで入ってから行う。`git -C` は使わない。EnterWorktree と ExitWorktree は許可のダイアログが出るので使わない
- 環境設定・非公開資料は必要な対象だけ準備する。`.worktreeinclude` がある場合も内容を確認し、`wt step copy-ignored --from <source> --to <target> --require-include --dry-run` で対象を確認してから、同じ指定で `--dry-run` を外してコピーする。依存関係は各 worktree 内で独立して準備し、別 worktree の node_modules 等の依存ディレクトリを丸ごと共有する symlink は作らない（パッケージ管理ツール内部の正規の symlink は対象外）。`.worktreeinclude` がない場合は必要なファイルを個別確認し、無差別な copy-ignored や `--force`、既存先の上書きをしない。秘密値を表示しない。
- 開始元の最新の指示ファイルと、存在する `ROADMAP.md` / `doc/ROADMAP.md` / `progress.txt` の正本を確認する。Git管理外の資料は引継ぎ先でも読めるよう必要な対象だけ用意し、コピー側から正本へ並行上書きしない。正本の更新は統括側で集約する。
- PR がマージされたら、消す前にセッションの作業場所をメインの作業ツリー（`git worktree list` の先頭の行のパス。<基点> のブランチとは限らない）へ `cd` だけの1回の呼び出しで移す。消す worktree の中にいたまま消すと、そのあとは存在しない場所でシェルが起動できず、`/clear` のあとも次の作業がその場所で始まる。worktree に入ったときに出る「元のリポジトリへ cd しない」という案内は、片付けでは当てはめない。移ったら次の呼び出しで `pwd` と `git rev-parse --git-dir` を見て、作業場所がメインの作業ツリーで `.git/worktrees/` の下でないことを確かめてから消す
- PR がマージされたら worktree とローカルブランチを消す: `gh pr view <番号> --json state` で `MERGED` を確かめ、先に PR の基点ブランチ（main や develop。以下 <基点>）を最新にする。最初に `git fetch origin <基点>` を実行する。`git fetch origin <基点>:<基点>` は reference-transaction の hook にいつも止められるので使わない。<基点> がどこかの worktree でチェックアウトされていれば、その worktree で `git merge --ff-only origin/<基点>` を実行する（`git pull` は pull.rebase の設定だと未コミットの変更があるだけで失敗する）。「would be overwritten by merge」で止まったら、挙がったファイルごとに `git diff origin/<基点> -- <ファイル>` を見る。出力が空で、かつ `git diff --cached -- <ファイル>`（HEAD との差）も空のファイルは、sandbox が書き込めずに PR の中身のまま残ったものなので、`git add <ファイル>` でステージしてから、もう一度 `git merge --ff-only origin/<基点>` を打つ。中身が同じファイルは git が書き直さないので通る。どちらかに出力があるファイルは手元の変更（ステージ済みの編集を含む）なので触らず、早送りをやめて報告する。<基点> がどこにもチェックアウトされていなければ、早送りはしない。元の worktree のブランチは切り替えない。そのあとメインの作業ツリーで `wt remove <branch> --foreground --no-hooks --format json` を実行する。<基点> が古いままだと squash マージしたブランチを未マージと判定して残すので、順番を守る。`-f` と `-D` は付けない。未コミットの変更があると何も消さずに止まる。出力の `branch_outcome` が `deleted` でなければ、聞かずに `~/mac_home/hooks/wt-remove-merged -C <メインの作業ツリー> --into origin/<基点> <branch>` を実行する。`--into` で比べる先を、fetch で最新にした origin/<基点> にするので、メインの作業ツリーが別のブランチでも判定できる。この入口がない環境では実行しない。取り込み済み（ブランチを <基点> にマージしても中身が変わらない）なら消えるので報告する。取り込まれていなければ何も消さずに止まる。`wt remove -D` は直接打たない。マージ前の worktree は消さない
- PR のブランチが worktree ではなくメインの作業ツリーでチェックアウトされているときは、メインの作業ツリーで `git switch <基点>` をしてから、上の `wt remove` を実行する（worktree がないのでブランチだけが消える）。切り替えると <基点> がチェックアウトされた状態になるので、`wt remove` の前に、上の項目の `git merge --ff-only origin/<基点>` で早送りする。「would be overwritten by merge」で止まったときも、上の項目と同じ扱いにする。未コミットの変更が残っていても、確認を挟まずに切り替える。切り替えで変更が失われるなら git が拒否するので、拒否されたときだけ止めて、拒否されたファイルを報告する。この切り替えは「元の worktree のブランチは切り替えない」の例外にする。切り替えずに止まると、`wt remove` は「The main worktree cannot be removed」で何も消さない。<基点> を最新にする操作が hook に止められても、`git fetch origin` で `origin/<基点>` が最新なら取り込み済みと判定されて消える
- 消し終えたら、`git worktree list`、worktree のフォルダの有無、`git branch --list <branch>` で、フォルダとブランチの両方が消えたかを確かめる。`wt remove` の出力だけで消えたと報告しない
- フォルダかブランチが残ったら、すぐユーザーに渡さず、本当に消せないかを確かめ直す。残った worktree で `git status --short --untracked-files=all` を見る、<基点> が最新かを見直す、など止まった出力から原因を1つに絞る。<基点> が古いなど自分で直せる原因なら、直して上の手順をやり直す。未コミットや未追跡のファイル、<基点> に取り込まれていない変更など、消すとデータが失われる原因なら自分では消さない
- 確かめ直しても消せないときは、ユーザーに削除を頼む。報告には、残ったフォルダの絶対パスとブランチ名、消せない理由（確かめたコマンドと、その出力の要点1行）、ユーザーが打つ削除のコマンドを書く。理由を書かずに「ユーザーが手動で消す」とだけ報告しない
- 片付けの報告には、今いる場所の絶対パスを1行書く
