# CodexによるHerdr統括

このスキルはCodexの統括セッション用である。作業者として呼ばれた場合は親の担当範囲に従い、独断で子を起動しない。リポジトリの個別運用、既存の安全・Worktrunk・Git push禁止ルールを維持する。

## 開始前

Herdrを制御する前に `test "${HERDR_ENV:-}" = 1` で管理ペイン内にいることを確認する。この環境変数はHerdrの利用可否だけに使い、統括／作業者の役割判定には使わない。Herdr外ならHerdrを操作せず、利用可能な内部サブエージェントを検討する。利用手段がなければ、導入や設定変更を勝手に行わず制約を報告する。

`herdr --skill` と `herdr --help` を読み、必要な `agent` / `pane` コマンドのhelpで現行構文を確認する。インストール済みCLIを正本とし、古いスキル例をそのまま実行しない。探索のために引数なしの変更コマンドを実行しない。

## 担当と引継ぎ

テスト作成・実装・レビューは別の新規セッションで始め、`resume` / `fork` や会話履歴の丸ごと継承で兼用しない。要件、仕様、公開インターフェース、完了条件、作業先の絶対パス・ブランチ・基点、変更可能範囲、検証コマンド、禁止操作を必要な範囲で渡す。資料の正本と非公開扱いも伝える。

長い指示は非公開・Git管理外の引継ぎファイルに保存し、最初のpromptは役割・担当・ファイルパスに絞る。子がその資料を読めることを確認し、秘密値は指示や端末に展開しない。シェルへ渡す値は安全に引用する。

- テスト担当: 要件から期待値を決め、可能なら修正前の再現テストが期待する原因で失敗することを記録する。本体実装は行わない。実装担当の解法を期待値の根拠にしない。
- 実装担当: 要件と確定したテストを渡す。テストの変更は禁止する。必要な修正があれば統括が仕様と照合してテスト担当へ返す。
- レビュー担当: 要件、仕様、最終差分、検証結果を渡し、read-onlyで確認する。仕様外れ、境界条件、失敗系、テスト値への決め打ち、不足検証を具体的な失敗シナリオで報告する。

軽微な文言だけの変更では不要なテストを増やさず、適切な機械検証と独立確認を選ぶ。セッションを分けるだけで誤りがなくなるとは扱わない。

## ペインと起動

まず `herdr pane layout --current` で既存配置を確認する。基本は左右2列で左を統括、右上を作業、右下をレビューにする。利用可能な幅と既存作業を優先し、不要にペインを増やさない。splitは必ず直列に実行し、返されたJSONの実在するペインIDを次の操作に使う。

```bash
herdr pane split --current --direction right --cwd '<作業先の絶対パス>' --no-focus
```

右列を分ける必要があるときは、返された右側IDを対象に `--direction down` と `--no-focus` を使う。名前やIDを推測せず、ユーザーのフォーカスを奪わない。

同じworktreeの編集者は常に1体とする。テスト担当が終了してから実装担当へ引き継ぎ、再委譲前に旧担当が編集を止めたことを確認する。独立した実装項目は既存のWorktrunkルールに従って分離する。環境を変更するテストと実装を並行させない。

利用可能なモデルからグローバル指示の担当別初期値を選ぶ。CLI用IDはSolが `gpt-6.1-sol`、Terraが `gpt-6.1-terra`、Lunaが `gpt-6-luna`、Astraが `gpt-6-astra`。モデルが使えなければ許可内の代替か制約報告とし、利用可能と見なして先へ進めない。

新規の空きシェルペインへ起動する例:

```bash
herdr agent start implement-task --kind codex --pane '<返されたペインID>' -- --model gpt-6.1-sol --config 'model_reasoning_effort="high"' --sandbox workspace-write
```

native Codex引数は `--` の後へ渡す。`agent start` の成功は同じペインでCodexが認識され、入力可能になったことを示す。起動がblockedになったら `agent get` / `agent read` で内容を確認する。

権限は親と同等以下に保つ。実装・テストは許可された範囲のworkspace-write、レビューは `--sandbox read-only` を基本とし、親がread-onlyなら編集担当を起動しない。起動前に親の実効権限・承認方針を確認し、子の既定設定と異なる制約はnative引数と引継ぎで維持する。権限拡大・承認迂回の引数や設定を追加しない。

## 依頼と待機

```bash
herdr agent prompt implement-task '役割: 作業者。担当: 実装。再委譲禁止。引継ぎファイル: <絶対パス> を読み、指定範囲だけを作業する。' --wait --timeout 45000
```

短い待機を繰り返し、待機中も進捗を伝える。timeoutや`agent_prompt_stalled`でも依頼が未送信とは判断しない。`agent get` と `agent read` を確認し、workingが続くなら同じ依頼を再送せず待機を続ける。

```bash
herdr agent get implement-task
herdr agent read implement-task --source recent-unwrapped --lines 120
herdr agent wait implement-task --timeout 45000
```

blockedなら画面の承認・質問内容を読み、既存の承認境界に従って扱う。権限不足を自動承認や別経路で迂回しない。45秒のtimeoutだけで作業失敗やブロックとは判定しない。

## 検証と完了

`idle` / `done`など見た目の状態だけで完了にしない。自分で作った子の応答を読み、差分、実行した検証コマンド、結果、未検証範囲、未解決事項を確認する。必要な機械検証と独立レビューが通るまで未完了とする。レビュー後に差分を変えたら関連する検証とレビューをやり直す。

他者の既存端末を終了しない。自分で作成した子のペインは、担当の作業終了と結果・差分・検証・引継ぎの確認が済み、必要な内容を非公開の記録へ残して不要になったら自動で閉じる。作業中、承認待ち、未読の結果や未完了の担当があるペインは閉じない。閉じる直前にもペインIDと担当の同一性・停止状態を確認する。コミット・push・merge・worktree削除などの自動化は追加しない。
